# tvt-lab

A Podman Compose Grafana stack seeded with known telemetry waste and known dependencies: the test bed for `../tvt`. `ground-truth.yaml` is the expected classification of every signal. Keep it in sync with any change to `shop/app.py`, the rules or the dashboards.

- `make up` / `make up-mimir` / `make down` / `make validate` / `make check-live` / `make autostart` (macOS: restart on VM boot + VM at login). Never `make reset` casually: tvt needs 30+ days of history.
- Image versions are pinned in both `compose.yaml` and `Makefile`. Bump them together.
- Use fully qualified image names (`docker.io/...`) so Podman doesn't prompt for short-name resolution.
- Grafana is plain HTTP on http://localhost:3000 (admin/admin).
- Live usage logs in `./lab-logs` (gitignored): the Prometheus query log is bind-mounted at `lab-logs/prometheus/query.log`, and Loki and Mimir log to `lab-logs/loki.log` and `lab-logs/mimir.log` through Podman's `k8s-file` driver (CRI lines). tvt reads them live because each scan's probe query must show up in them (tvt Sprint 2 item 4). Compose's logging paths must be absolute, so run compose through `make`, which exports `LAB_LOGS`. The option is `max-size`; Podman silently ignores `max_size`.
- The `viewer` service simulates browser views of the Shop Overview dashboard only. Legacy Queue must stay unviewed.
- Grafana-managed alert: `shop_order_export_lag_seconds` is read only by the provisioned rule in `grafana/provisioning/alerting/shop-alerts.yml`. Ground truth expects it as hard_keep. Grafana reads alert provisioning only at start: after adding or changing a file there, `podman compose restart grafana`, then `make check-live`.
- Recreating Prometheus (a changed flag or compose entry): use `make up-mimir`, or `PROM_CONFIG=prometheus-mimir.yml LAB_LOGS="$PWD/lab-logs" podman compose --profile mimir up -d prometheus`. A plain `podman compose up -d prometheus` falls back to `prometheus.yml`, which has no `remote_write`, and Mimir silently stops receiving data (happened Nov 15, 2026 20:2x–22:28 UTC; tvt's Mimir e2e then fails with "no metric costs").
- Mimir profile: the one-shot `mimir-rules` service (curl) loads `mimir/rules/shop.yml` into Mimir's ruler, namespace `tvt-lab`, on every `make up-mimir`. Its recording rules copy `shop-recording` with a `ruler: mimir` label so they don't collide with the series Prometheus remote-writes. `NodeLoadHigh` makes `node_load15` hard_keep for a `--mimir` scan only (`mimir:` in ground truth). The ruler picks up new rules within about a minute.
- The /healthz scenario: successful health checks are logged into the same info/api stream as real traffic (about 64% of its bytes). Ground truth expects tvt to report the pattern and hand it to zeroreads (`line_handoff`), not to generate a line filter or touch the stream. Loki's pattern ingester is enabled for this.
- Declared-only metrics (tvt Sprint 2 item 7): `shop_checkout_attempts_total` is read only by the Sloth SLO in `slos/` (not loaded into Prometheus), and `shop_payment_gateway_retries_total` only by the query step in `runbooks/payment-queue-backlog.md`, which `ShopPaymentQueueBacklog` links as its `runbook_url`. Both are hard_keep. After changing the shop: `podman compose up -d --build shop`; after changing rules: `curl -X POST localhost:9090/-/reload`.
- Alloy pipeline (tvt Sprint 2 item 14, ADR 0007; since Nov 15, 2026 22:23 UTC): the `alloy` service (`alloy/config.alloy`, its directory standing in for a pipeline repo) scrapes the shop and node-exporter with the same `job`/`instance` labels Prometheus used, through a no-op `prometheus.relabel "apps"`, and remote-writes them to Prometheus; the shop pushes its logs to Alloy's `loki.source.api` (`:3500`, incoming timestamps kept) and on through a pass-through `loki.process "apps"` to Loki. Prometheus scrapes itself and the backends (`prometheus/scrape/lab.yml`). The reconciler's stream bypasses Alloy (`RECONCILER_LOKI_URL`): the one signal no pipeline claims. Ground truth `pipelines:` uses tvt's `examples/tvt.example.yaml` names and handles. Prometheus no longer has target metadata for shop and node (`/api/v1/targets` lists only its own jobs). After changing the config: `LAB_LOGS="$PWD/lab-logs" podman compose restart alloy`, then `make check-live`. Verify with the series API or Alloy's UI, not PromQL: queries land in the query log tvt reads.
- Grafana Cloud output (tvt S6 item 6; Nov 15, 2026): `make cloud` recreates only Alloy (`--no-deps`) with `ALLOY_OUTPUT=cloud`, which mounts `alloy/outputs/cloud.alloy` beside `config.alloy` and forwards a free-tier subset (shop and node metrics minus `_created` and feature-flag `user_id` series; shop streams minus api debug) to the Grafana Cloud test stack; `make cloud-off` (or the default `local`) mounts `outputs/local.alloy`, which drops everything. Credentials only from the shell's `GCLOUD_*` variables (a write-only token), never this repo; `make cloud` refuses to start without them. `ALLOY_OUTPUT=cloud make check-live` checks Alloy's own `/metrics` that samples and log bytes reach Cloud with none failed. Ground truth `cloud:` lists what Cloud has and which seeds stay local. `alloy validate` checks syntax only (it passes dangling references), so a config change needs a real start.
- Grafana Cloud test stack (Nov 16, 2026): example-stack, a trial (ends about Nov 30). The shell's `GCLOUD_HOSTED_METRICS_ID`/`_LOGS_ID` are its instance IDs (1000001, 1000002) and `GCLOUD_RW_API_KEY` a write token from its own org (policy `tvt-lab-write`); an earlier stack on the same clusters had different IDs, and mixing the two gives 401 on every call. After changing them, rerun `make cloud` here and `make cloud-secret && make cloud` in `kps/`. tvt reads the stack with `tvt scan --grafana-edition cloud` (tvt `docs/grafana-cloud.md`).
- kube-prometheus-stack on kind (`kps/`, tvt-lab #23 and #25): `make up` (Podman provider; the VM needs about 8 GB with the lab), `make fixtures` (chart 93.3.0 rendered for tvt's tests), `make cloud` (remote write of ~2.3k of ~35k series with `cluster="tvt-kps"`, `retryOnRateLimit`), `make series` (local vs Cloud per job, fails over 2,500). The free tier's 10k series hold the lab's ~7k plus this. On kind the etcd, controller-manager, scheduler and kube-proxy targets are down, so their alerts fire: left as shipped.
- Overflow seed (tvt S6 item 5; since Nov 16, 2026 00:06 UTC): the shop sends a span per request (OTel Python SDK, OTLP/HTTP to Alloy's `otelcol.receiver.otlp` on :4318, `customer.id` over 500 customers); `otelcol.connector.spanmetrics` keeps `http.route` and `customer.id` as dimensions with `aggregation_cardinality_limit = 100`, so `traces_span_metrics_*` carry overflow series (`otel_metric_overflow="true"`, only `job`/`le` kept). The viewer's ad hoc `traces_span_metrics_calls_total{customer_id="c-0042"}` filters on a capped label. Ground truth `overflow:`. The span metrics and `target_info` stay out of the Cloud output. After the Podman machine restarts from the LaunchAgent, compose's API socket is `/private/tmp/podman/podman-machine-default-api.sock` (set `DOCKER_HOST=unix://...`); `podman` itself works over ssh.
- SLO coverage (tvt S6 item 3): `slos/shop-availability.sloth.yml` has its fast-burn page alert loaded (`prometheus/rules/slo-burn.yml`, `ShopAvailabilityBurn`, multiwindow 1h and 5m, severity critical); the checkout SLO declares `ShopCheckoutSLOBurn`, which no ruler loads. Expected findings under ground truth `slo_coverage:` (services are the owners listed there; paging = severity critical).
- Mentioned-only metrics (tvt S4 item 3): `node_load15` is named in the prose of `runbooks/payment-queue-backlog.md` (outside its query step) and `node_context_switches_total` in `postmortems/2026-10-24-checkout-slowdown.md` (point `postmortems.paths` in tvt.yaml at `postmortems/`). Nothing queries either, so both are `dormant_confirm`: tvt asks the owner, never proposes a drop.
- Absence alert (tvt Sprint 2 item 18): `ShopInventorySyncMissing` is `time() - shop_inventory_sync_last_success_timestamp_seconds{job="shop"} > 600 or absent(...)`, the only reader of that gauge (and its `job` label). It returns nothing while healthy: hard_keep, and never a "rule returned nothing" finding. `INVENTORY_SYNC=stale` or `missing` (compose env, default `ok`) makes the staleness or absent() branch fire.
- `~/Documents` files can be evicted by macOS (`ls -lO` shows `dataless`); the Podman VM then gets `input/output error` on bind-mounted config, and a container restarted at VM boot can hit it too. The durable fix is to keep the lab out of iCloud-synced `~/Documents` (or turn off Optimize Mac Storage). Until then, before reloading or recreating a container, read the bind-mounted directories from the repo root: `cd "$(git rev-parse --show-toplevel)" && find alertmanager grafana loki mimir prometheus viewer -type f -print0 | xargs -0 cat >/dev/null`, then check `find alertmanager grafana loki mimir prometheus viewer -flags +dataless`.
- S5 distractors (tvt S5 item 2), none of which may change a recommendation: `shop_cart_operation_total` (one letter off the read `shop_cart_operations_total`, never read: drop_metric), the `reconciler` service in the shop container logging one identical error line every `RECONCILER_ERROR_SECONDS` to `{app="reconciler", component="worker", level="error"}` (dormant_confirm: an error stream, never a saving), and Shop Overview panel 9, which reads `${counter}` (a custom variable over two already-read counters). The viewer replays panel 9 with the variable's current value.
- Startup burst (tvt S5 item 3): every shop start logs one identical warn line `STARTUP_BURST_LINES` (5000) times into the warn/api stream. Loki's pattern ingester keeps it for about 3 hours, so the repeated-line finding shows only in that window after `podman compose up -d --build shop` (or a restart). The line is logfmt on purpose: the pattern ingester tokenizes a logfmt stream as logfmt and silently finds no pattern in a plain-text line (Loki still stores it).
- Lab states (tvt S5 benchmark, S15 `--as-of`): `ground-truth.yaml` describes the current lab, and its `states:` section lists what an earlier state had differently. `before-deploy` ends with the deploy that added `ShopHealthcheckSlow` (`prometheus/rules/healthcheck.yml`, loaded Nov 15, 2026 03:35 UTC), which made `shop_healthcheck_duration_seconds_bucket` a hard keep. tvt keeps a frozen fixture snapshot of each side in `testdata/bench`. A new state needs a new snapshot captured right before and after the change.
- Rule-efficiency seeds (tvt Sprint 2 item 12, findings in tvt S6 item 1; `rule_findings:` in ground truth): `prometheus/rules/rule-efficiency.yml` (a `[24h]` window every 1m, a 5s group on a 10s scrape, an alert on the never-existing `shop_legacy_export_batches_total`, a duplicate of `ShopHighErrorRate`), the Grafana-managed `Shop checkout errors (logs)` (LogQL `| logfmt` on the error stream every 30s, no line filter) and its well-built version: the Loki recording rule `shop:checkout_errors:count5m` (`loki/rules/fake/shop-checkout.yml`), remote-written into Prometheus (`--web.enable-remote-write-receiver`, Loki `ruler.remote_write`), read by `ShopCheckoutErrorsFromLogs`. The Grafana alert makes the error stream hard_keep (it was keep_high; `states: before-rule-efficiency`). After changing `loki/loki.yml` or Loki rules: `LAB_LOGS="$PWD/lab-logs" podman compose restart loki`.
- How rule evaluations show in the query logs (checked Nov 15, 2026, Grafana 12, Loki 3.5, Prometheus 3.5): Grafana's Loki alert evaluations are ordinary `component=frontend` metrics.go lines (`query_type=metric`, `range_type=instant`, `length=0s`) with no `source`, user or rule header, so only the query text, the instant type and the 30s cadence tie them to the rule; the Loki ruler's own evaluations are `component=ruler` lines. Grafana's Prometheus evaluations are `POST /api/v1/query` instant queries from Grafana's IP with no user agent. Both logs carry per-evaluation cost: Loki `total_bytes`/`total_lines`, Prometheus `stats.samples.totalQueryableSamples`. Restarting Grafana can change its container IP (10.89.0.17 → .29 on Nov 15).
- Fluent Bit pipeline (tvt S7, ADR 0009; since Nov 17, 2026 02:11 UTC): the shop writes its debug api lines to `/var/log/shop/debug.log` (`DEBUG_LOG_FILE`, rotating at 50 MB, two backups) in the `shop-logs` volume instead of pushing them through Alloy; the `fluent-bit` service (`fluent-bit/fluent-bit.yaml`, its directory standing in for a pipeline repo) tails it and ships `{app="shop", component="api", level="debug"}` to Loki, lines unchanged (`drop_single_key: raw`). Alloy now handles only the info, warn and error shop streams (ground truth `pipelines:`: `alloy-apps` and `fluentbit-shop-debug`). The shop image creates `/var/log/shop` owned by `nobody`, so a fresh volume takes that owner. `make validate` dry-runs the Fluent Bit config.
- Compose from this shell: the docker-compose provider needs `DOCKER_HOST=unix://$TMPDIR/podman/podman-machine-default-api.sock` (the machine was started with that `TMPDIR`; `podman machine inspect` reports `/tmp/podman/...`, which doesn't exist). Recreate single services with `--no-deps`, or Alloy is recreated without `ALLOY_OUTPUT=cloud`.
- Disk-full gap (Nov 16, 2026 about 07:00 UTC to Nov 17 02:07 UTC): the Podman VM's root partition was 16.5 GB of its 30 GB disk and filled. Prometheus and Loki rejected writes, Mimir crashed, and Alloy's remote-write WAL stuck on a bad segment. Fixed by `growpart /dev/vda 4` and `xfs_growfs /` inside the VM (now 30 GB), restarting Alloy and starting Mimir. Any tvt window that covers that period has a hole. Prometheus's `retention.size=20GB` plus Loki and Mimir can still outgrow 30 GB in a few weeks: watch `podman machine ssh df -h /`.
- Alloy rewrites (tvt S7 item 9, ADR 0013; since Nov 17, 2026 02:20 UTC): the shop's `shop_search_queries_total` is renamed in `prometheus.relabel "apps"` to `shop_search_requests_total`, the only name Prometheus stores; Shop Overview panel 10 (replayed by the viewer) reads it, so it's keep_high. The span metrics now pass `prometheus.relabel "spans"`, whose drop rule's regex is `sys.env("TVT_LAB_SPANS_DROP_REGEX")` (compose sets a name no metric has): an evidence gap on `traces_span_metrics_*` and `target_info`, never a reader or a drop. Ground truth `rewrites:`. Alloy needs that variable: recreate it with `make cloud` (or `cloud-off`), not a plain restart, after changing compose; `make validate` passes it too.
- OTel Collector and synthetic coding agent (tvt S7; since Nov 17, 2026 02:18 UTC, logs labelled correctly from 02:22): `genai-agent` (`genai-agent/agent.py`, OTel Python SDK 1.36) sends made-up coding-agent telemetry every 30s to `otelcol` (contrib 0.165.0, `otelcol/config.yaml`): interaction, llm_request and `execute_tool` spans (to `nop`: the lab has no trace backend), `api_request`, `tool_decision` and `tool_result` log records (Loki OTLP, one stream `{service_name="coding-agent"}` with `event_name` and the attributes as structured metadata), and delta counters `coding_agent_token_usage_total` and `coding_agent_cost_usage_USD_total` with `session_id` and `user_email` (`delta_to_cumulative`, then remote write; one series per session). A `batch` processor sits in every pipeline as a seed. Contrib 0.165 warns on the old component names: use `otlp_http`, `prometheus_remote_write`, `delta_to_cumulative`. The first minute's 14 log records went to `{service_name="unknown_service"}` (the SDK's `LogRecord` needs `resource=`). Ground truth `genai_agent:` and `pipelines: otelcol-agent`.
- Records (tvt S7 item 2, ADR 0011): ground truth `records:` lists the audit stream, the coding agent's `tool_result` and `tool_decision` log events, and its successful `execute_tool` spans (including `rollback_deploy`, about one interaction in 40). tvt must never drop, sample or collapse them; capping a content attribute is fine when the outcome fields stay.
- Mac mini host (since Nov 17, 2026 04:43 UTC; the MacBook lab is stopped, gap from about 03:10): Apple M1, 8 GB, Podman 6.2 (Podman Desktop) with a libkrun machine of 4 CPUs, 5 GB and 80 GB. Its internal disk has about 4 GB free, so the machine's disk image lives on the Storage drive (`~/.local/share/containers/podman/machine/libkrun` is a symlink to `/Volumes/Storage/podman/libkrun`) and the lab runs from `/Volumes/Storage/Code/Telemetry Value Tracker/tvt-lab`. Podman shares only `/Users`, `/private` and `/var/folders` by default: `/Volumes/Storage` was added to the machine's JSON `Mounts` (tag = first 36 hex of sha256 of the path), and `volumes-storage.service` inside the VM mounts it with `context=system_u:object_r:container_file_t:s0` (without it SELinux denies every bind-mounted config). After the volume import the volume roots were root-owned, so Prometheus, Loki and Grafana couldn't write: `import-volumes.sh` now restores the owner `export-volumes.sh` records. Its `~/.docker/config.json` names Docker Desktop's missing `credsStore`, so run compose with `DOCKER_CONFIG=~/.config/tvt-lab-docker` (an empty config). `make autostart` is installed. tvt on the MacBook reaches the lab through an SSH tunnel to `user@lab-host.local` (ports 3000, 3100, 9009, 9090, 9093, 12345).
