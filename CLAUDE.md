# tvt-lab

A Podman Compose Grafana stack seeded with known telemetry waste and known dependencies: the test bed for `../tvt`. `ground-truth.yaml` is the expected classification of every signal. Keep it in sync with any change to `shop/app.py`, the rules or the dashboards.

- `make up` / `make up-mimir` / `make down` / `make validate` / `make check-live` / `make autostart` (macOS: restart on VM boot + VM at login). Never `make reset` casually: tvt needs 30+ days of history.
- Image versions are pinned in both `compose.yaml` and `Makefile`. Bump them together.
- Use fully qualified image names (`docker.io/...`) so Podman doesn't prompt for short-name resolution.
- Grafana is plain HTTP on http://localhost:3000 (admin/admin).
- Live usage logs in `./lab-logs` (gitignored): the Prometheus query log is bind-mounted at `lab-logs/prometheus/query.log`, and Loki and Mimir log to `lab-logs/loki.log` and `lab-logs/mimir.log` through Podman's `k8s-file` driver (CRI lines). tvt reads them live because each scan's probe query must show up in them (tvt Sprint 2 item 4). Compose's logging paths must be absolute, so run compose through `make`, which exports `LAB_LOGS`. The option is `max-size`; Podman silently ignores `max_size`.
- The `viewer` service simulates browser views of the Shop Overview dashboard only. Legacy Queue must stay unviewed.
- Grafana-managed alert: `shop_order_export_lag_seconds` is read only by the provisioned rule in `grafana/provisioning/alerting/shop-alerts.yml`. Ground truth expects it as hard_keep. Grafana reads alert provisioning only at start: after adding or changing a file there, `podman compose restart grafana`, then `make check-live`.
- Mimir profile: the one-shot `mimir-rules` service (curl) loads `mimir/rules/shop.yml` into Mimir's ruler, namespace `tvt-lab`, on every `make up-mimir`. Its recording rules copy `shop-recording` with a `ruler: mimir` label so they don't collide with the series Prometheus remote-writes. `NodeLoadHigh` makes `node_load15` hard_keep for a `--mimir` scan only (`mimir:` in ground truth). The ruler picks up new rules within about a minute.
- The /healthz scenario: successful health checks are logged into the same info/api stream as real traffic (about 64% of its bytes). Ground truth expects tvt to report the pattern and hand it to zeroreads (`line_handoff`), not to generate a line filter or touch the stream. Loki's pattern ingester is enabled for this.
- Declared-only metrics (tvt Sprint 2 item 7): `shop_checkout_attempts_total` is read only by the Sloth SLO in `slos/` (not loaded into Prometheus), and `shop_payment_gateway_retries_total` only by the query step in `runbooks/payment-queue-backlog.md`, which `ShopPaymentQueueBacklog` links as its `runbook_url`. Both are hard_keep. After changing the shop: `podman compose up -d --build shop`; after changing rules: `curl -X POST localhost:9090/-/reload`.
- Mentioned-only metrics (tvt S4 item 3): `node_load15` is named in the prose of `runbooks/payment-queue-backlog.md` (outside its query step) and `node_context_switches_total` in `postmortems/2026-10-24-checkout-slowdown.md` (point `postmortems.paths` in tvt.yaml at `postmortems/`). Nothing queries either, so both are `dormant_confirm`: tvt asks the owner, never proposes a drop.
- Absence alert (tvt Sprint 2 item 18): `ShopInventorySyncMissing` is `time() - shop_inventory_sync_last_success_timestamp_seconds{job="shop"} > 600 or absent(...)`, the only reader of that gauge (and its `job` label). It returns nothing while healthy: hard_keep, and never a "rule returned nothing" finding. `INVENTORY_SYNC=stale` or `missing` (compose env, default `ok`) makes the staleness or absent() branch fire.
- `~/Documents` files can be evicted by macOS (`ls -lO` shows `dataless`); the Podman VM then gets `input/output error` on bind-mounted config, and a container restarted at VM boot can hit it too. The durable fix is to keep the lab out of iCloud-synced `~/Documents` (or turn off Optimize Mac Storage). Until then, before reloading or recreating a container, read the bind-mounted directories from the repo root: `cd "$(git rev-parse --show-toplevel)" && find alertmanager grafana loki mimir prometheus viewer -type f -print0 | xargs -0 cat >/dev/null`, then check `find alertmanager grafana loki mimir prometheus viewer -flags +dataless`.
- S5 distractors (tvt S5 item 2), none of which may change a recommendation: `shop_cart_operation_total` (one letter off the read `shop_cart_operations_total`, never read: drop_metric), the `reconciler` service in the shop container logging one identical error line every `RECONCILER_ERROR_SECONDS` to `{app="reconciler", component="worker", level="error"}` (dormant_confirm: an error stream, never a saving), and Shop Overview panel 9, which reads `${counter}` (a custom variable over two already-read counters). The viewer replays panel 9 with the variable's current value.
- Startup burst (tvt S5 item 3): every shop start logs one identical warn line `STARTUP_BURST_LINES` (5000) times into the warn/api stream. Loki's pattern ingester keeps it for about 3 hours, so the repeated-line finding shows only in that window after `podman compose up -d --build shop` (or a restart). The line is logfmt on purpose: the pattern ingester tokenizes a logfmt stream as logfmt and silently finds no pattern in a plain-text line (Loki still stores it).
- Lab states (tvt S5 benchmark, S15 `--as-of`): `ground-truth.yaml` describes the current lab, and its `states:` section lists what an earlier state had differently. `before-deploy` ends with the deploy that added `ShopHealthcheckSlow` (`prometheus/rules/healthcheck.yml`, loaded Nov 15, 2026 03:35 UTC), which made `shop_healthcheck_duration_seconds_bucket` a hard keep. tvt keeps a frozen fixture snapshot of each side in `testdata/bench`. A new state needs a new snapshot captured right before and after the change.
- Rule-efficiency seeds (tvt Sprint 2 item 12, findings in tvt S6 item 1; `rule_findings:` in ground truth): `prometheus/rules/rule-efficiency.yml` (a `[24h]` window every 1m, a 5s group on a 10s scrape, an alert on the never-existing `shop_legacy_export_batches_total`, a duplicate of `ShopHighErrorRate`), the Grafana-managed `Shop checkout errors (logs)` (LogQL `| logfmt` on the error stream every 30s, no line filter) and its well-built version: the Loki recording rule `shop:checkout_errors:count5m` (`loki/rules/fake/shop-checkout.yml`), remote-written into Prometheus (`--web.enable-remote-write-receiver`, Loki `ruler.remote_write`), read by `ShopCheckoutErrorsFromLogs`. The Grafana alert makes the error stream hard_keep (it was keep_high; `states: before-rule-efficiency`). After changing `loki/loki.yml` or Loki rules: `LAB_LOGS="$PWD/lab-logs" podman compose restart loki`.
- How rule evaluations show in the query logs (checked Nov 15, 2026, Grafana 12, Loki 3.5, Prometheus 3.5): Grafana's Loki alert evaluations are ordinary `component=frontend` metrics.go lines (`query_type=metric`, `range_type=instant`, `length=0s`) with no `source`, user or rule header, so only the query text, the instant type and the 30s cadence tie them to the rule; the Loki ruler's own evaluations are `component=ruler` lines. Grafana's Prometheus evaluations are `POST /api/v1/query` instant queries from Grafana's IP with no user agent. Both logs carry per-evaluation cost: Loki `total_bytes`/`total_lines`, Prometheus `stats.samples.totalQueryableSamples`. Restarting Grafana can change its container IP (10.89.0.17 → .29 on Nov 15).
